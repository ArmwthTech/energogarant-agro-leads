# energogarant-agro-leads: статус проекта на 2026-07-02

## Что сделали

Собран MVP веб-приложения для корпоративного страхового агента ЭНЕРГОГАРАНТ по лидам АПК Ростовской области.

Стек:

- Next.js App Router, TypeScript, Tailwind.
- Vercel-ready проект.
- ExcelJS для XLSX.
- Опционально Clerk Auth и Neon Postgres через env.
- Локальный сервер: `http://127.0.0.1:3000`.
- GitHub repo: `ArmwthTech/energogarant-agro-leads`, ветка `codex/initial-mvp`.

## Реализовано в интерфейсе

- Главный экран: таблица лидов.
- Фильтры: поиск по компании/ИНН/ОГРН, тип, статус, сортировка по потенциалу.
- Карточка лида вынесена на отдельную страницу `/lead/{inn}` и открывается в новой вкладке.
- Длинные названия компаний не ломают таблицу.
- Боковое меню ведет на реальные страницы: лиды, импорт, отчеты, агенты, настройки.
- Кнопка `Проверить контакты` ищет сайт, телефон и email по открытым источникам.
- Кнопка `Экспорт XLSX` генерирует Excel.
- Кнопка наверх.
- Страница лида содержит реквизиты, контакты и быстрые переходы в Яндекс, Google, VK, OK, 2ГИС.

## Данные

Текущие источники:

- ФНС ЕГРЮЛ через открытый веб-сервис: https://egrul.nalog.ru/
- Заготовки под РМСП, Минсельхоз Ростовской области и ЕИС закупки.
- Поиск сайта/контактов через открытые страницы и поисковую выдачу.

Что важно:

- ЕГРЮЛ не гарантирует стабильное число строк при веб-поиске.
- Если ФНС включает captcha, мы не обходим ее.
- Пустую выдачу ФНС больше не кэшируем как валидную базу.
- Live-данные сливаются с seed по ИНН, чтобы прямые ссылки на лидов не ломались.
- Последний браузерный smoke показал 141 лида после догрузки live-данных. Число может меняться из-за поведения источника.

## Почему нельзя просто спарсить все телефоны и email

Коротко: потому что в открытых официальных реестрах этих контактов обычно нет, а публичные сайты и каталоги не дают надежную, юридически чистую и полную базу.

Причины:

1. ЕГРЮЛ дает реквизиты юрлица, но не является справочником телефонов и email.
2. Веб-сервис ФНС защищается captcha. Обход captcha и антибот-защиты не используем.
3. Справочники часто показывают устаревшие или чужие контакты. Без проверки по ИНН/ОГРН можно записать телефон каталога, бухгалтера другой компании или общий саппорт агрегатора.
4. Телефон и email физлица могут быть персональными данными. Для обработки нужна законная цель, документы и режим доступа.
5. Рекламная рассылка/звонки по сетям электросвязи требуют предварительного согласия адресата. Наличие email в интернете не равно согласию на рекламу.
6. Соцсети часто требуют авторизацию и ограничивают автоматический сбор. Это нельзя превращать в обход защиты.

## Что нужно, чтобы набить базу максимально валидными лидами

Минимально правильный процесс:

1. Брать основу из официальных источников:
   - bulk-интеграция ФНС ЕГРЮЛ/ЕГРИП;
   - ЕИС закупки;
   - региональные реестры Минсельхоза;
   - реестры господдержки, субсидий, грантов.
2. Фильтровать компании по региону 61, ОКВЭД, названию и отраслевым маркерам: СПК, КФХ, колхоз, агро, зерно, элеватор, семена, молоко, мясо, птица, овощи, сад, виноград.
3. Для каждой компании искать официальный сайт и принимать его только если на странице найден ИНН или ОГРН.
4. Контакты делить на типы:
   - `corporate_verified`: общий корпоративный телефон/email с сайта компании;
   - `corporate_unverified`: найдено, но нет жесткого подтверждения;
   - `personal_unverified`: ФИО/личный телефон/email, не экспортировать и не рассылать;
   - `consent_ok`: есть отдельное основание для коммуникации/рассылки.
5. Добавить ручную проверку агентом: один клик `проверено`, комментарий, дата, источник.
6. Не использовать массовую рекламную рассылку до юридически оформленного согласия.
7. Для масштабирования использовать не парсинг выдачи браузера, а официальные/лицензированные источники:
   - ФНС bulk access;
   - XML/открытые данные ЕИС;
   - лицензированный API 2ГИС/Яндекс Бизнес/контуроподобного провайдера, если условия разрешают CRM enrichment;
   - собственный ручной обзвон и фиксация результата в системе.

## Что делать следующим шагом

1. Подключить Neon Postgres.

5. Добавить XLSX импорт/экспорт по фильтрам.
